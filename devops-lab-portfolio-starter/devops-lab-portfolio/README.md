## Working approach

For each task:

1. Read the brief and identify the deliverables.
2. Implement the solution in its own folder.
3. Run it and capture relevant validation output/screenshots.
4. Update that task's README with setup, commands, and results.
5. Commit and push that task separately.

## Safety and repository hygiene

- Never commit passwords, access tokens, private keys, `.env` files, or real credentials.
- Keep local virtual environments, build output, logs, and generated model weights out of Git unless a task explicitly requires them. Use Git LFS or a model hosting service for large required artifacts.
- Use placeholder values in examples and provide an `.env.example` when needed.
